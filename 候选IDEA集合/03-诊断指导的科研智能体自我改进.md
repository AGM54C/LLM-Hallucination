# 诊断指导的科研智能体自我改进

## 三句话说明

科研智能体即使修复了一次失败，也可能在后续任务中重复同类推理或验证错误，普通反思是否能够稳定消除这些失误需要检验。
本研究将 Agent 与 LLM 诊断得到的失败条件用于选择干预位置、修改方式和更新验收条件。
通过独立任务与跨轮次评价，检验这种诊断指导能否提高净修复收益、减少错误复发，并保持研究推进能力。

## 改进过程

1. **发现问题：**从任务执行中识别具有明确依据的推理或验证缺陷，未决科学结论保留未决状态。
2. **诊断与干预：**提出可检验的失败解释，由人或程序选择补充条件、改变验证方法、修改技能或控制逻辑等动作。
3. **检查修复：**重新执行受影响步骤，检查原问题是否改善、已有正确部分是否被破坏。
4. **接受更新：**结合独立检查、回归任务和必要的领域复核决定是否保留修改，并记录适用条件。
5. **检验迁移：**在未参与诊断和修改的任务上，检查相同失误是否减少以及其他能力是否退步。

首轮固定一种改进对象，例如技能或控制代码，并保存各轮版本。模型参数、任务记忆和评价器变化分别记录，避免同时改变过多因素而无法解释收益。若仅修改任务执行策略，结论限定为系统自我改进；若研究递归增能，还需独立检验后继版本是否更擅长产生下一轮有效改进。

## 对照与评价

比较未改进系统、同预算普通反思、自我改进加 Agent 诊断，以及进一步加入 LLM 内部诊断的版本。所有版本对齐任务、可用信息、工具、采样与计算预算；有人参与时，还需匹配人工信息和时间投入。隐藏测试答案及评价标签不用于指导修改。

评价当前任务的净修复收益、未见任务的同类错误复发、错误验证通过、回归退步、任务推进和总成本。先在可控任务检查干预作用，再在真实开放科研任务上评价有独立依据的环节与后续表现；不能把部分检查通过等同于科学结论获证。

例如，系统曾将共用错误前提的两个计算结果视为独立验证。诊断后的修改可以要求检查共同依赖，并在需要时从独立构造重新计算。应在不同科学对象和实现方式下检验这一改动能否迁移，同时比较简单的通用独立核验提示是否已经足够。

## 可形成的贡献

重点在于失败条件如何决定干预，以及更新后是否持续减少错误复发。需要证明针对性诊断优于相同成本的通用反思和检查，并单独检验 LLM 内部诊断的额外价值。

最终真值未知时，验收只能覆盖能够检查的环节；评价器需接受独立审计，不能把系统自己的高分作为可靠改进的唯一依据。若现有 RSI 已经稳定改善这些行为，则优先转向解释其有效机制与适用条件。

## 直接相关工作

- [SAGE](https://arxiv.org/abs/2606.31478v1)：已按科研失败解释选择假设、实验设计或实现层修复，需要明确新增贡献。
- [DeFA](https://arxiv.org/abs/2610.01256v1)：已有依赖诊断与后续技能进化结合，诊断接自我改进并非空白。
- [SEAL](https://arxiv.org/abs/2607.24300v1)：揭示自写验证的局限，并以独立审计验收更新。
- [RQGM](https://arxiv.org/abs/2606.26294v3)：代理与评价器共同演化，需关注评价标准漂移和误拒。
