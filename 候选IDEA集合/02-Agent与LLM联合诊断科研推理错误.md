# Agent 与 LLM 联合诊断科研推理错误

## 三句话说明

科研 Agent 的失败轨迹能够显示行为偏差，但仅凭日志往往难以区分信息缺失、上下文组织、工具反馈和模型内部信息使用等因素。
本研究结合 Agent 轨迹分析与执行模型内部分析，提出可以通过干预检验的失败解释。
在相同诊断预算下，检验内部信息是否帮助选对修复位置和方式，并改善未见任务中的诊断与修复。

## 两层诊断

| 层次 | 观察对象 | 重点问题 |
|---|---|---|
| Agent 诊断 | 计划、消息、上下文、工具调用、实验产物与验证依赖。 | 哪一步出现偏差，关键条件是否进入上下文，错误如何影响后续判断？ |
| LLM 诊断 | 执行模型在关键步骤的隐藏状态、信息可读出性及选择性激活干预。 | 模型如何表示和使用相关条件，内部变化是否对错误行为有可重复影响？ |

能力是行为表现，机制解释表现如何产生，两者并非互斥分类。一次失败不能证明模型绝对不会；探针读不出某项信息，也不能直接证明该信息不存在于模型内部。

## 初步实验

先从 IDEA 01 中选择稳定复现、具有局部判据的错误，保留完整输入、执行状态与成功对照。以同一错误出现前的状态为起点，提出多个候选解释，例如条件未提供、条件已提供但未正确使用、验证过程共用错误依赖。

分别尝试补足任务允许获得的信息、调整上下文组织、替换验证方法等干预，实际重新执行并检查后续结果。内部诊断首先使用可访问权重的执行模型；探针用于形成假设，再通过选择性激活干预及无关位置对照检验其作用。

比较轨迹诊断、轨迹加内部诊断，以及同预算的强模型直接诊断。事后诊断可以查看完整轨迹及后来获得的观测；判断某一步当时的推断是否合理，仍需依据该步可得信息。隐藏参考状态和评价标签仅用于外部核验。记录候选解释、依据、干预动作、修复效果和新引入的错误。

主要评价干预选择是否有效、净修复收益、误修复和跨任务迁移。定位准确率作为辅助指标；Who&When 类受控归因任务用于方法检查，科研自然错误承担应用验证。

## 可形成的贡献

目标是证明某类内部信息能在轨迹诊断之外提供稳定、可操作的增益，并对具体失败条件给出受干预支持的解释。某次修改修好了错误，不等于发现唯一根因；多个干预可能通过不同路径改善结果。

内部诊断若没有额外收益，应据实界定适用范围。已有 HCI 工具提供了日志对齐、人工检查与重跑能力，新增界面或可视化本身不足以支撑机制贡献。

## 直接相关工作

- [InconLens](https://arxiv.org/abs/2603.28106v1)：跨运行信息里程碑对齐与行为分歧分析。
- [DoVer](https://arxiv.org/abs/2512.06749v3)：将诊断解释转成干预并重新执行，直接相关于诊断有效性的检验。
- [ReCast](https://arxiv.org/abs/2610.11334v1)：使用读取日志的诊断 LLM 的表示；不能将其表征分析等同于观察原执行模型内部状态。
- [Latent Critic](https://arxiv.org/abs/2608.10430v1)：内部信号到局部反馈的实例，主要验证工具参数的上下文依据，迁移到科研推理需另行检验。
