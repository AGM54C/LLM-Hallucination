# V1 · 选样与普通训练

**结论：这次高分歧选样没有胜过普通 SFT。** 普通训练有效，但不能把所有提分归因于选样原则。

同一 Qwen3-14B，5 个 LoRA 训练臂；每臂 128 个训练案例、80 次更新，seed 41。正式评价共 18,900 条决策，来自一个实验来源。

## 为什么做、验证什么

答对一个训练样本，不一定需要遵守题目指定的条件。例如，“对所有底物取平均后选最高”也可能碰巧答对某个底物的问题。本轮检验：**优先训练那些能区分正确条件规则与指定错误规则的样本，是否比普通选样更有效、更耐受换序？**

这里的“分歧”有明确而有限的定义：两条手写规则——忽略目标底物、选全表平均最高项；只看第一种底物、选最高项——各自答错记 1 分，总分为 0–2。它不是多模型意见分歧，也不是从模型内部观测出的推理方式。

## 五个训练臂为何这样设置

| 训练臂 | 实际方法 | 要验证什么、为何需要它 |
|---|---|---|
| 普通选样 `uniform` | 从合格训练池随机选 128 例，使用原序 | 测普通监督微调能带来多少提升，作为选样策略的参照。 |
| 低分歧 `low_disagreement` | 在匹配约束下最小化两条错误规则的答错总数 | 这些样本较难区分正确规则与捷径；与高分歧形成方向相反的对照。 |
| 高分歧 `high_disagreement` | 在相同匹配约束下最大化上述总数 | 检验“能排除更多指定捷径的样本更值得训练”这一候选选样原则。 |
| 顺序增强 `random_order_augmentation` | 与普通臂使用完全相同的 128 例，每例换成固定打乱的记录顺序 | 检查仅改变训练呈现是否足以提高换序表现。实际实现每例只有一种打乱版本，不是每轮重新随机。 |
| 难例 `hard_examples` | 根据基座对正确答案的负对数似然（NLL）选高损失样本 | 对照“选更难的样本”这一解释；难度来自模型损失，不等于产率差距小。 |

合格池共 583 例，只含训练划分中有唯一最高值的任务，避免单答案训练标签任意选取并列项。整数规划让低分歧、高分歧、难例臂匹配普通臂的来源、添加剂组、正确化学选项、答案别名、产率差距区间、字符长度区间和基座 NLL 四分位区间的**各自计数**。这样减少可见混杂，但没有固定这些属性的联合分布，也没有精确匹配连续难度。

所有臂均用普通答案交叉熵训练，只监督答案部分；LoRA rank 8、学习率 1e-4、batch 1、梯度累积 4。固定模型、样本数、更新数和超参数，是为了让选样成为主要比较对象；它仍不保证不同臂的总输入 token 或训练动态完全相同。

## 怎样评价、为何不只看原序

| 对照 | 方法与目的 |
|---|---|
| 未训练基座与五臂 | 比较微调前后，避免把普通 SFT 的收益误归给特定选样策略。 |
| 最高值与最低值 | 同一证据分别要求选最高、最低，检查是否遵守比较方向；训练只用了最高值，最低值也是目标迁移检查。 |
| 原序、逆序、完全打乱 | 内容和正确答案不变，检查决策对记录顺序的依赖。 |
| 结构化字段、检查提示 | 分别改用 `context / option / yield` 字段，或提醒检查条件和比较方向；检查低成本提示改变能否改善表现。 |

验证集 330 题、测试集 360 题，最高/最低各占一半；评分接受任一并列最优项。看准确率，也看选错造成的产率损失和跨呈现表现。高分歧若只胜过低分歧、却没有稳定胜过普通选样和难例，就不足以说明有独立选样收益。

**方法性质：候选改动是选样目标。** LoRA、交叉熵和整数规划均为已有工具；本轮没有新损失函数、内部状态监督或神经机制干预，也尚未证明新的选样贡献。

## 结果与边界

最大值、原序表现：

| 模型或训练臂 | 验证准确率 | 测试准确率 |
|---|---:|---:|
| 未训练基座 | 84.85% | V1 未运行，V2 补齐为 83.89% |
| 普通选样 | 96.97% | 96.11% |
| 低分歧 | 92.73% | 90.00% |
| 高分歧 | 90.91% | 92.78% |
| 随机顺序增强 | 89.70% | 86.67% |
| 难例 | 97.58% | 96.11% |

每格验证 165 例、测试 180 例。完整目标、呈现和损失见 [metrics.csv](metrics.csv)，不能只看原序。

两个限制影响解释：高分歧只覆盖 32 个条件块，普通臂覆盖 39 个；连续难度也未完全匹配。因此只能说这个具体策略未胜出，不能严格否定规则区分性的独立价值。

普通臂测试最大值从原序 96.11% 降到全打乱 73.33%，促使后续实验转向呈现控制。旧测试集已经参与开发，不能继续充当新方法的独立确认集。
