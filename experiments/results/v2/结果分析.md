# V2 · 顺序与独立读出

**结论：保持同目标的四条记录相邻时较稳，完全打散会明显降低直接选择准确率。** 独立读值后用程序比较是强基线。

## 为什么做、验证什么

V1 的原序高分在完全打乱后下降，但完全打乱同时改变了记录位置、相邻关系和检索跨度。本轮先拆开这些变化，再分别检查“按编号抄值”“按条件找值”“作最终选择”，确定后续应关注哪一类行为困难。

## 实验 A：拆分记录顺序

两模型固定表格内容、问题和别名，只改行序；在验证集最高/最低共 330 题上评价。

| 条件 | 怎么改、为什么这样改 |
|---|---|
| 原序、全表逆序 | 提供原序参照和整体翻转对照；逆序仍保留同一底物的四条记录相邻。 |
| 底物块换序 | 以同一底物的四条记录为一个块，仅打乱块位置；检查整块出现在表中何处的影响。 |
| 块内换序 | 保持各块位置，只打乱块内四个选项；检查局部选项排列的影响。 |
| 全表打乱 | 不保留块结构；检查目标记录分散后是否更难处理。 |

后三种各用 seed 0、1、2，减少只观察一个排列的偶然性。若只有全打乱明显下降，支持“分散呈现带来额外困难”，但无法在跨度、位置和邻近关系之间识别唯一原因。位置审计记录了这些变化，没有把它们逐一匹配。

## 实验 B：独立读出与程序比较

本组只用验证集最高值 165 题、原序与全打乱 seed 0；不是对全部最低值任务做过读出诊断。每个呈现分别发出三个独立请求，不向下一个请求传入前一个回答。

| 条件 | 方法 | 要验证什么、设计依据 |
|---|---|---|
| 指定记录读值 `value` | 直接给目标记录编号，要求抄出数字 | 检查已给定行位置时能否复制数值；它额外提供定位信息，难度低于自主找行。 |
| 条件关联读值 `relation` | 给目标底物，要求列出各选项的产率 | 同时要求定位条件、关联选项与数字，检查显式提取是否可行。 |
| 直接选择 `decision` | 从完整表格直接给出选项 | 保留原任务，用来与显式读值流程比较。 |
| 关联读值→程序比较 | 对模型实际读出的数字确定性取最大值 | 不增加模型调用，检查把最后比较交给程序能达到多少；使用读数本身，不替换为真值。 |

读值采用严格 JSON 格式，数值容差为 0.0005 个产率百分点。读值和直接选择之间的差异只能说明不同请求方式的行为差异，不能证明直接选择时模型内部已经存有正确数值。

**方法性质：顺序扰动、任务分解和程序比较都是诊断对照。** 本轮没有训练改动、隐藏状态探针或激活替换；也未建立一种新的内部机制。

## 结果与边界

验证集最大值任务：

| 呈现 | 原始模型 | 普通 SFT |
|---|---:|---:|
| 原序 | 84.85% | 96.97% |
| 全表逆序 | 83.64% | 94.55% |
| 底物块换序，三种排列平均 | 85.45% | 95.96% |
| 块内换序，三种排列平均 | 82.42% | 94.34% |
| 全表打乱，三种排列平均 | 64.24% | 74.55% |

原序与逆序各 165 次，三种排列共 495 次，仍是同一批任务的重复测量。全打乱同时改变位置、跨度与邻近关系，尚不能识别唯一内部机制。

全打乱 seed 0 下，模型独立读出数值后交给程序比较，最大值准确率达到原始模型 98.79%、普通 SFT 100%。这些读出和原直接决策来自不同请求，不能据此断言原轨迹“已经知道但没有使用”。

V2 还补齐基座测试最大值：原序 83.89%、全打乱 61.67%。最小值目标与最大值不同，完整结果见 [summary.json](summary.json)。

补齐基座测试是为了给 V1 已评价的微调模型提供同划分参照，不是新增的独立确认。全打乱 seed 0 与 V1 的对应提示一致，因此可用于核对跨轮结果；后续 V3 在显式读值基础上直接测试比较步骤。
