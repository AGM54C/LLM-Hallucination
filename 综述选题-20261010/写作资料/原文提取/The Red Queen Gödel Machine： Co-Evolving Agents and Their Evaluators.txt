1  INTRODUCTION


Self-improving agents aim to turn gains in coding and reasoning into a recursive loop, where each
stronger agent can produce better variants of itself. Search methods such as the Darwin and Hux-
ley Gödel Machines (DGM and HGM) [1, 2] set the open-source state-of-the-art on agentic cod-
ing tasks by editing their own code and retaining variants that improve an external utility signal.
HyperAgents [3] then extended this self-improvement beyond coding to task agents in arbitrary
domains. Despite this progress, current search methods still depend on stationary evaluation fixed
outside the improvement loop. This is unlike biological evolution, where, under Van Valen’s Red
Queen hypothesis [4], each species adapts to competitors that evolve in turn. This dependence con-
strains self-improvement when a target task has no direct benchmark, as for paper and proof writing,
unlike paper reviewing and proof grading [5–7], when evaluation is slow or weakly informative [8–
10], and when static benchmarks saturate or become vulnerable to reward hacking [11, 12].
We introduce the Red Queen Gödel Machine (RQGM), an evolutionary framework that treats eval-
uation as part of the search process. We study this through co-evolved learned evaluators, which
improve alongside the task agents they guide. Such an evaluator can supply the search signal when
no benchmark exists, add criteria a benchmark cannot capture, or act as a cheaper proxy. The core
mechanism is controlled utility evolution, which divides search into evolutionary epochs. Within an
epoch, one evaluator is frozen and grades every task agent, supplying a stationary utility signal. In
parallel, the search co-evolves challenger evaluators with their task agents and scores them against
a held-out ground-truth dataset. At an epoch boundary, a challenger replaces the frozen evaluator
only if it raises the incumbent’s best-belief score on a replacement criterion; the RQGM then ap-
plies selective erasure, discarding only utility records that depended on the replaced evaluator. Each
epoch is thus a fixed-criterion search problem, so HGM’s guarantees apply within each epoch (Sec. 3
and App. F). Since validity requires only a fixed within-epoch utility and boundary erasure of de-
pendent records, time-varying benchmarks and adversarial objectives fit the same structure.
On DeepSWE [13], the RQGM coder running at low reasoning reaches a held-out pass rate of 82.1%
against the HGM-H baseline at 75.0%. The RQGM with low reasoning also matches the base GPT-6
Astra model in the mini-SWE-agent harness at high effort, and reaches 85.7% at medium or
high effort (Fig. 1). On Polyglot, the RQGM reaches 71.7% against 69.9% with fewer search
tokens (Fig. 3). This illustrates a broader advantage of the RQGM: shared expansions can improve
multiple utilities at once, since most accepted expansions edit code shared by the coder and re-
viewer (Fig. 11). We then turn to scientific paper writing and reviewing, and Olympiad-level proof
writing and grading, where only reviewing and grading have a benchmark. Co-evolved writers raise
reviewer-panel acceptance from 21.8% to 40.5% (Tab. 2), while a co-evolved grader exceeds the
static baselines with a 3× lower search cost than HGM-H (Fig. 6). Co-evolution can also regularize
evaluators: replaying AI-generated papers accepted by a displaced reviewer as adversarial samples
produces a reviewer equally stringent on machine-written and human-written work (Fig. 7). Given
the pace of model improvement, we believe automatically evolving the benchmarking process is
needed for AI systems to exceed what static evaluation alone can achieve.

     This supports both learned evaluators that act as agents-as-judges for downstream tasks and more gen-

2  RELATED WORK

Self-Improving AI.  The Gödel Machine [14] is a theoretical construct that rewrites its own
code whenever it can prove that doing so is beneficial. A recent line of work makes this construct
empirical by replacing proof search with archive search over observed utility. The Darwin Gödel
Machine [DGM, 1] ranks self-modifying coding agents by benchmark utility, the Huxley-Gödel
Machine [HGM, 2] scores nodes by clade metaproductivity rather than their own score, and
HyperAgents [3] extends self-modification beyond coding tasks by making each node an editable
meta-agent/task-agent codebase. These systems hold their evaluation criterion fixed outside the
loop, exposing them to benchmark saturation [12], judge biases [15, 16], and reward hacking [17].
The RQGM departs from this line of work by pulling the evaluation criterion itself inside the loop,
searching over the evaluators that define the utility.

Co-Evolving Evaluation.  Recent work co-adapts generators and rewards within the gradient-
based training of a single model [18–20] or co-evolves evaluation metrics with agent skills un-
der ground-truth guards [21]. By contrast, the RQGM operates in the search space of agentic code-
bases, preserving HGM’s epoch-local validity while gating every evaluator promotion on an evaluator-
independent ground-truth anchor. In doing so, it guards against the self-referential drift documented
in self-rewarding training [22, 23]. A further survey of related work can be found in App. H.

3  RQGM: CO-EVOLVING AGENTS AND THEIR EVALUATORS

As visualized in Fig. 2, the RQGM is a search over an archive T where each node is a shared, evolv-
able workspace containing task agents, evaluators, and a meta-agent that oversees the workspace.
Expansion creates an edited child starting from the parent. Since the meta-agent and role-agent code
are editable, roles may reuse each other’s code if the meta-agent deems it useful. Only the scor-
ing and orchestration harness are fixed. Departing from prior work, the RQGM introduces controlled
utility evolution to co-evolve agents and their evaluators (Sec. 3.2). Details are in App. B.

3.1  SEARCH SPACE AND UTILITY

The RQGM enables the evaluation of tasks without ground-truth signal via distinct evaluator roles. In
addition to evaluator-independent roles that use fixed benchmarks (App. B.1), evaluator-dependent
roles use learned evaluators, each held in an independently replaced evaluator slot.
Self-improvement as tree search. Following Wang et al. [2], the archive T at time 𝑡(T𝑡) grows
from a root agent 𝑎0. Each step either expands a node, adding an edited child, or evaluates a node
on one task, adding a binary outcome to its successes 𝑆𝑎or failures 𝐹𝑎. Expansion occurs via a
UCB-Air gate [24] when the number of evaluations is sufficient (see App. B.2). A node’s own
success rate poorly predicts what its descendants achieve, so Thompson sampling selects expansion
parents by clade metaproductivity, the rate pooled over the subtree 𝐶(𝑎) rooted at 𝑎, CMP(𝑎) =
𝑆𝐶𝑎/(𝑆𝐶𝑎+ 𝐹𝐶𝑎), and evaluation targets by their own (𝑆𝑎, 𝐹𝑎). Under a fixed criterion, a CMPd oracle
suffices to implement the Gödel Machine (Thm. 1).

3.2  CONTROLLED UTILITY EVOLUTION

In fixed-criterion search, learned evaluators cannot co-evolve with the agents they score. To en-
able the co-evolution of evaluators and their agents, we first assume epoch-local stationarity: each
evaluator, node workspace, and scoring rule stays fixed within an epoch, the interval between two
checkpoints (Asm. 2). At specific checkpoints (epoch boundaries), learned evaluators may be re-
placed if they fulfill the following criterion (App. B.3).
Ground-truth evaluator replacement. At each checkpoint, every evaluator slot compares its in-
cumbent against challengers on a ground-truth anchor, a fixed held-out dataset of objective or human
labels. The highest anchor best-belief wins, with ties retaining the incumbent. A slot may also re-
ward rejecting an adversarial pool of outputs its displaced evaluator had accepted (Sec. 4); without
one, the evaluator-independent anchor keeps one criterion across epochs (App. F.2.1).

For fixed 𝜖∈(0, 1), the Beta mean and quantile converge to 𝑄(𝑒) when their samples consistently
estimate that same objective. Each utility record 𝑧carries the set dep(𝑧) of slots whose evaluator
affected its generation, sampling, replay, or scoring. Upon replacement on slot 𝑚, selective erasure
removes every record 𝑧with 𝑚∈dep(𝑧) written under the displaced evaluator, since keeping or
rescaling it would mix evidence from two utilities. Other records and all artifacts are unaffected, and
node and clade statistics are recomputed (Def. F.2 and Prop. 2).

  Epoch-Local Validity. Stationary generation and scoring give each node–role–task tuple a fixed success
   probability. With selective erasure, each epoch is a fixed binary-outcome search problem (Props. 3 and 5),
   to which HGM’s analysis applies within the epoch under its remaining assumptions (Asm. 1).

Amortized utility-transition cost. Re-scoring the entire archive after every erasure wastes budget
on nodes the search may never revisit. To avoid this, the RQGM re-scores old nodes on demand,
using cached outputs without additional task-agent calls beyond the new evaluator. In addition, we
use exponentially spaced checkpoints to bound total cost (App. B.3).

  Bounded Recovery. Fix one evaluator slot and a budget of 𝐵evaluations. If each checkpoint reprocesses
   at most all prior slot-dependent records, the total is bounded by 𝜌𝐵/(𝜌−1) for checkpoint ratio 𝜌> 1.
  Reassessing all prior records after every evaluation would require O(𝐵2) work (Prop. 6 and Rem. 2).

4  EXPERIMENTAL DESIGN

Domains and ground-truth anchors. Paper writing and review are paired, anchored to APReS
accept/reject decisions [25]. Proof writing and grading are anchored to IMO-GradingBench hu-

man grades [7], where a proof is accepted only when the epoch’s frozen grader awards full credit (7
of 7). Coding uses two benchmarks, each with two anchors. On Polyglot [26], the coding agent
is anchored to executable tests, with the code reviewer anchored to CRAVE [27], a dataset of accept-
ed/rejected pull requests. On DeepSWE [13], the coder is anchored to the benchmark’s tests, and
the code reviewer to a balanced dataset of publicly available accepted/rejected patches (App. C.6).
Reward design follows HyperAgents [3]: a task agent writes a reward function, and a quadruped
policy trained on it with PPO is scored on forward walking during search and on jumping held out. Its
utility is continuous, so we slightly adapt the HGM utility and search prior (App. B.5). Appendix C.8
details the splits, curriculum, and protocol.
Data splits. Every dataset is divided into train, validation, and held-out test splits. The meta-agent
may request task-agent results only on the train split, which informs its edits. Node selection and
evaluator replacement are driven solely by the validation split. The held-out test split is never seen
during search and is used only for post-hoc scoring of search-selected agents. Appendix C.6 de-
scribes how each dataset is split. We show the initialization of each role in App. C.9.
Baselines. Every headline domain uses a learned baseline, HGM-H [2, 3], which replaces the DGM
search algorithm of HyperAgents [3] with the more sample-efficient HGM, while keeping evalu-
ators frozen. We use the Sakana prompt reviewer [5] for paper writing, ProofAutoGrader [7]
for proof grading, and the IMO25 prover [28] for proof writing. We evaluate the best published
HyperAgents (DGM-H) patches from Zhang et al. [3] for paper reviewing and grading as a proxy
for DGM-level performance. We selected GPT-5.5 (low) for experiments unless otherwise stated.
For DeepSWE, we move to GPT-6 Astra [29], the strongest model on the DeepSWE leaderboard
at the time of writing, with a high-effort meta-agent and low-effort task agents in both arms. For the
reward design domain we use Nemotron 3 Ultra.
Search interventions. In paper writing/reviewing and on DeepSWE, we use controlled utility evo-
lution to challenge evaluators with outputs accepted by previous evaluators. After replacement, the
papers or patches the displaced evaluator had accepted form an adversarial pool. Subsequent eval-
uator selection rewards rejecting these generated outputs alongside performance on the labeled ex-
amples. We ablate these mechanisms in App. D.2. For reward design we use a curriculum over the
difficult of the task as a form of evolving utility.
Costs and reporting. Best-belief is comparable across epochs only when it rests on a fixed ground-
truth anchor, so a global best-belief winner exists only for anchored roles: the learned evaluators and
the verifiable coding agent. The paper writer and prover have no anchor and admit only epoch-local
winners, each the best agent under its epoch’s frozen evaluator; we select these per epoch and score
them post-hoc against fixed external judges (Tabs. 2 and 3). We compare headline runs at matched
search tokens rather than evaluation counts, since evaluations differ in cost; we report blended to-
kens: input plus output, with output weighted at 5× input cost [30, 31], counting both generation
and evaluation calls. Following Wang et al. [2], a best-belief agent’s cost is measured when it first
attains its highest 𝜖-best-belief score, not when the epoch or run finishes. Specialist nodes are those
that maximize best-belief on one target utility; a generalist is a node that maximizes the average
best-belief across its active utilities (App. C.3). When the specialist and generalist coincide on the
same node, we report a single result.

5  RESULTS

Our results show that where ground truth exists, a co-evolved evaluator provides a complemen-
tary objective and finds stronger agents than fixed-evaluator search (Sec. 5.1). Where no bench-
mark exists, it supplies the search signal, and co-evolved agents outperform fixed-evaluator base-
lines (Sec. 5.2). Evaluator replacements act as a curriculum, re-ranking the archive toward new
candidates around a resilient backbone (Sec. 5.3). Finally, co-evolution improves the evaluators
themselves, and adversarial objectives correct failure modes such as self-preference (Sec. 5.4).

plementary surrogate to the ground-truth signal. We also study reward design, where ground truth
exists but non-stationary utilities can still improve search.

5.3  EVALUATOR REPLACEMENTS ACT AS A CURRICULUM ON THE SEARCH (RQ3)

A mechanism by which the RQGM can improve task agents is that a progressively harsher evaluator
imposes a curriculum-like effect on the task agents. For this, each evaluator transition must re-rank
the search under the stricter criterion while preserving strong lineages, so that the search advances.
Macro view: each replacement re-ranks the archive. If replacements merely sharpened pass-rate
estimates without changing which agents the search favors, no curriculum could arise. Figure 4
shows that part of the ranking persists across a transition, since evaluator-independent evidence car-
ries through, but the re-ordering never recovers. Without erasure the ranking remains highly stable.

5.4  CO-EVOLUTION IMPROVES THE EVALUATORS THEMSELVES (RQ4)

Proof grading. As shown in Fig. 6, the co-evolved grader is the strongest judge, outperforming the
static baselines and the best HGM-H grader at 3× lower search cost; the specialist and generalist co-
incide in a single node. This better grader drives the prover gains of Tab. 3. Similarly, on DeepSWE,
only the top reviewer rejects most failing patches (Tab. 15) with the others being overly lenient.
Paper review. The HGM-H reviewer scoring writers in Tab. 2 accepts AI-generated papers at 1.42×–
1.91× the rate of human ones. After each evaluator replacement in the RQGM, the AI-generated
papers the displaced reviewer had accepted form an adversarial pool, and the next epoch additionally
rewards evolved reviewers for rejecting them. As shown in Fig. 7, the search then selects a reviewer
that is harsh specifically on AI-generated text, which costs raw accuracy by construction and leaves
our best-found reviewer below the lenient HGM-H. However, this calibrates the reviewer to accept
AI-generated and human-written papers at similar rates while retaining 80% ground-truth accuracy.

6  CONCLUSION

We introduced the Red Queen Gödel Machine (RQGM), a framework in which evaluators co-evolve
with the agents they score. Through controlled utility evolution, the search objective can change at
epoch boundaries while remaining fixed within each epoch, which has three consequences. First,
where ground truth exists, a co-evolved evaluator adds a complementary search signal, and co-
evolved coders outperform the HGM-H baseline on both coding benchmarks. Second, co-evolving
 the evaluator alongside the generator enables improvement on hard-to-verify tasks such as paper and
 proof writing, where a fixed benchmark cannot score the artifact directly. Third, the search can adopt
 interventions that a fixed objective cannot express, such as a curriculum or an adversarial term. At
 longer horizons, we believe these mechanisms could help push the frontier of AI capabilities.

ETHICS STATEMENT

This work automates the writing and reviewing of scientific papers, which carries a dual-use risk:
automated writers could be used to flood peer review with generated submissions, and automated
reviewers could be deployed in place of human judgment. No generated paper was submitted to any
venue or shown to human reviewers, and all reviewing experiments use the public APReS dataset.
Our results bear on this risk directly: fixed LLM reviewers accept AI-generated papers more readily
than human ones, and the RQGM’s adversarial objective produces a reviewer that is equally stringent
on both. We view calibrated automated evaluation as a safeguard for peer review, not a replacement
for it. The work involves no human subjects or personal data.

B  METHOD DETAILS AND ALGORITHM

B.1  SEARCH SPACE

Roles and task pools. Each node is a workspace holding 𝐾roles R made up of task agents and
evaluators, plus a meta-agent that edits the workspace [3]. Each role 𝑟is scored on its own task
pool D𝑟; a paper reviewer, for example, has one task for human-written and one for agent-generated
papers. Since each task belongs to one role, we follow HyperAgents in calling every role’s agent
a task agent when the role is clear.
Evaluator slots and epochs. An evaluator-dependent role is scored through an evaluator slot whose
epoch index counts its replacements. The 𝑀≤𝐾slots are replaced independently, so their indices
form an epoch vector 𝒋∈N𝑀, and replacing one slot advances one entry.
Epoch-local utility. Writing 𝑝𝑟,𝑑,𝒋(𝑎) for node 𝑎’s success rate on task 𝑑under epoch vector 𝒋, the
utility of Sec. 3.1 becomes 𝑈𝒋(𝑎) = 𝐾1 Í𝑟   | D𝑟|1 Í 𝑑∈D𝑟𝑝𝑟,𝑑,𝒋(𝑎). We average uniformly rather than
by sample count because some tasks can generate unboundedly many evaluations.
Data isolation. Feedback that creates nodes is kept apart from evidence that selects them (Sec. 4).
For evaluator-independent roles, the splits of App. C.6 do this directly. For evaluator-dependent
roles, the task agent generates fresh artifacts for training and for search, and only the search artifacts,
scored by the epoch’s frozen evaluator, enter the utility.

B.2  THREE-LEVEL SAMPLING HIERARCHY

The scheduler of Wang et al. [2] interleaves expansion and evaluation. With 𝑁𝑡evaluations per-
formed and expansion exponent 𝛼∈(0, 1), a UCB-Air gate [24] expands when 𝑁𝛼𝑡  ≥|T𝑡| and
evaluates otherwise, so the archive grows as O(𝑁𝛼𝑡). An expansion draws its parent 𝑎★by Thomp-
son sampling over CMP. An evaluation draws 𝑎★over its own counts, then descends two lev-
els: the least-evaluated eligible role 𝑟★= arg min𝑟𝑛𝑟(𝑎★), then its least-evaluated eligible task
𝑑★= arg min𝑑∈D𝑟★𝑛𝑑(𝑎★). A task is eligible unless its dataset is exhausted; a role is eligible if
any of its tasks is. Outcomes accumulate at the node, and the role and task counters only balance
load. Under this balancing, the pooled Beta posterior mean converges to 𝑈𝒋(𝑎) (Prop. 1).

B.3  CO-EVOLVING EVALUATION AND CONTROLLED UTILITY EVOLUTION

Section 3.2 states the replacement rule, selective erasure, and checkpoint schedule. Formally, a utility
transition (Def. F.2) replaces a slot’s evaluator and erases only the records that depended on it;
evaluator replacement is one instance, and time-varying benchmarks or adversarial objectives fit
the same structure. Old nodes are re-scored only when later evaluations return to them, and the
sampling hierarchy above balances roles and tasks within each selected node. Exponentially spaced
checkpoints keep the total record reprocessing linear in the budget (Prop. 6) and let later evaluators,
each promoted on its own anchor, steer the rest of the search.

B.5  CONTINUOUS UTILITIES

Reward design scores each evaluation in [0, 1] rather than as pass or fail. To accommodate this, we
modify the CMP to be the average utility over a node’s subtree. The Beta posteriors behind Thompson
sampling and best-belief become Student-𝑡posteriors over the mean utility, the exact marginal of a
Normal–Gamma prior when the variance is unknown.

We order tasks by the failures of three reference models from the trial record, Claude Fable 5,
Claude Opus 5, and GPT-5.6 Sol, across all five reasoning efforts (6,679 scored trials). A
task’s difficulty key is the lexicographic tuple of its per-effort failure rates, ordered from max to low
effort, so a task that resists a stronger attempt always ranks as harder. This key separates 106 of the
113 tasks, against only 25 for a key built from the max-effort failure rate alone.
We allocate whole repositories, never individual tasks, so no codebase appears in two splits. Among
400 seeded greedy allocations refined by equal-size repository swaps, we keep the partition that
best matches the three splits on the max-effort failure rate, the pooled failure rate across efforts, and
language shares. The result has 28 train, 57 validation, and 28 test tasks. Validation is the largest
split because it carries the search signal.
Each task contributes one coder row and two reviewer rows in the same split: an accepted patch,
taken from a real passing trial, and a rejected patch, taken from a real failing trial of the same three
models. The rejected patch is chosen at the highest reasoning effort that failed (80 of 113 come from
max effort) and, within it, as the most nearly correct attempt, with a mean of 91% of verifier tests
passing. Both patches are model-written, so the pair differs in correctness alone. This gives 56, 114,
and 56 balanced review rows. Neither role sees the verifier tests or the reference solution.

a fixed seed, balanced at 50 accepted and 50 rejected, and disjoint by paper. The writer dataset of

Provers are scored on 20 held-out IMO problems by the fixed grader panel of Tab. 3.

C.8  REWARD-DESIGN CURRICULUM

Task. We port the Genesis reward-design domain of HyperAgents [3]. The task agent re-
ceives a one-sentence task description and writes a compute_reward function for a Unitree Go2
quadruped. A fixed host then trains a fresh PPO policy on that reward (4,096 parallel environments,
101 iterations) and evaluates checkpoint 100 for 1,000 steps under the host’s own fixed fitness, so the
generated reward shapes training but never scores itself. During search the task is to walk forward
at a commanded speed in [0.2, 0.8] m/s, scored by command-tracking fitness in [0, 1]. The held-out
task is jumping as high as possible, scored by maximum torso height in meters; a trial counts as a
jump when it exceeds the 0.3494 score. The static arm and the curriculum arm share every setting
except the curriculum.
Curriculum. The obstacle is composed of two 0.8 m-high slabs meeting at a right angle, initially
placed 2 m ahead of the robot; the robot starting positions are spread ±0.25 m sideways, so some
robots walk straight into the obstacle/corner and others pass it. The observation carries no extero-
ception, so the policy must respond to the obstacle from its own state. Stalled forward progress and
backing away from the obstacle cost fitness. The validation pool grows by extension:

• Stage 1 (from evaluation 1): two rows of the original walking task.
• Stage 2 (from evaluation 20): adds two rows with 0.5 m-wide slabs.
• Stage 3 (from evaluation 50): adds two rows with 1.0 m-wide slabs, which are hard to walk around
  once the robot is caught in the corner between them.

The task objective of walking forward remains on obstacle rows, with the fitness re-weighted partly
from speed tracking toward holding heading. The training rows follow the same schedule, and the
static arm keeps its six walking rows.
Protocol. We run five searches per arm to 125 evaluations, where both arms publish comparable
numbers of agents (22.0 and 21.2 per run on average). Each run’s best-belief agent then writes six
fresh jumping rewards; each is trained and evaluated once, and the run’s score is the mean of the six.
A generated reward that fails to load scores 0. Every PPO run draws a fresh seed.
Cost. Both arms use Nemotron 3 Ultra at high reasoning for the meta-agent and task agent. Per
run, the static arm spends 325 PPO trainings and 48.3M blended search tokens, and the curriculum
arm 291 trainings and 53.8M (Tab. 1). HyperAgents reports about 600 trainings and 33.6M tokens
with Claude Sonnet 4.5 over about 100 agents per run, which would be about $104 at list
price [31], compared with $24–$27 for our runs at Nemotron 3 Ultra list price [33], a 3.85–
4.33× reduction in cost.

D.3  WHERE COST AND PROGRESS COME FROM

D.3.1  COST DECOMPOSITION

Every model call is an expansion, a train-time evaluation, or a validation evaluation. Validation
dominates: across the three GPT-5.5 runs it carries 65–69% of blended tokens, expansion 18–
23%, and train-time evaluation 12–14% at three train samples per node (Fig. 10).
The DeepSWE runs follow the same pattern with a smaller expansion share, since each evaluation
is a long agentic episode: validation carries 68% and 70% of the RQGM and HGM-H runs, train-time
evaluation 29% and 26%, and expansion 4% and 3% (Tab. 14). Before each winner was generated,
most tokens went to the train-time evaluations the meta-agents request while editing.

D.3.2  PATCH SURFACES

We classify each accepted patch by the code it modifies. Shared surfaces, task-agent code and infras-
tructure used by more than one role, carry 59–90% of accepted patches in every GPT-5.5 run and
dominate in Polyglot (Fig. 11); the Nemotron 3 Super run instead targets the meta-agent’s
instruction module in 42% of edges. On DeepSWE, 83% of RQGM code patches do (App. E.5).


D.4  REDUCING SEARCH COSTS VIA HYBRID-MODEL APPROACHES

Expansion is only about 20% of search cost (Fig. 10). We therefore keep the GPT-5.5 (low) meta-
agent and route search-time task-agent calls through Nemotron 3 Ultra [35].
This cuts price-equivalent search cost by about 13× while nearly matching the GPT-5.5-only run’s
held-out accuracy on the 100 APReS test papers (Fig. 12).

E.4  THE DEEPSWE CODE REVIEWER

The DeepSWE code-review slot was replaced 11 times across 8 distinct reviewers, three times before
the winner was generated, at 47M, 160M, and 309M search tokens (Fig. 1). The seated reviewer’s

gain came from evidence. Later reviewers read the repository before deciding. The second writes an
acceptance checklist from the task statement alone, before seeing the patch, then inspects source in
up to three rounds. The last and strongest applies the patch to a scratch copy with Git.
Does anchor promotion carry over to the search?  Promotion only checks a reviewer on the
anchor, so we ask whether the promoted reviewer also judges the coder patches the search produces
more accurately. Every search-time verdict is joined to the test result of the patch it judged (Tab. 15).

F.1.1  OPERATING CONDITIONS

  Assumption 1 (Fixed-criterion search). Within one fixed-criterion epoch:
  C1. Only the agent selected after the budget is spent is scored; intermediate outcomes guide
       search but are not rewards.
  C2. Repeated evaluations of a fixed node–task pair are binary outcomes with a time-invariant
       success probability.
  C3. Any oracle or proof object in the ideal HGM theorem lies outside the empirical budget.
  C4. Expansions and evaluations are charged against the externally fixed budget.

Item C2 is the one RQGM must work to keep. HGM relies on a fixed evaluator for it; RQGM freezes
learned evaluators within an epoch (App. B.3), changes them only at checkpoints, and erases records
that depended on a displaced evaluator (App. B.3); all results below assume Asm. 1.

F.2  ONE RULE FOR REPLACEMENT AND SELECTION

Evaluators are frozen within an epoch. At a checkpoint, each slot promotes the candidate with the
highest 𝜖-best-belief on its anchor, optionally combined with an adversarial pool, and the winner
stays frozen for the whole next epoch (App. B.3).

G  LIMITATIONS

Our analysis assumes stationarity within each epoch (App. F.4); provider-side model updates or
nondeterministic tools can weaken this assumption in practice.
The reviewer panel measures cross-reviewer acceptance, and the generated papers and proofs were
scored by automated panels rather than human experts.
The anchor bounds what evaluator evolution can achieve. A weak, noisy, or biased anchor lets eval-
uators drift across epochs, and APReS decisions and IMO-GradingBench grades are themselves
imperfect. A good anchor keeps evaluators accurate but confines them to its own decision boundary,
so gains beyond the benchmark must come from objectives layered on top of it.

H  EXTENDED RELATED WORK

This section extends Section 2 with a broader overview.

Self-Improving AI.  Good [36] proposed a machine that designs better machines long before one
was feasible, and Schmidhuber [14] made the idea precise with the Gödel Machine. Of its empirical
successors (Sec. 2), HGM [2] starts from the observation that an agent’s benchmark score poorly pre-
dicts the value of its descendants, and reports human-level coding-agent performance while scoring
clades instead. HyperAgents [3] pairs each node’s task agent with a meta-agent that improves it,
so the improvement mechanism is itself editable. Related systems self-modify scaffolds or runtime
logic [37–39], refine prompts [40] or reasoning traces [41], self-tune for a domain [42], or hill-
climb [43]. Two surveys organize the field, as a closed lifecycle of data, selection, optimization, and
inference supervised by an evaluation layer [11], and by what is improved and how fully the loop is
closed [44]. Both describe fixed evaluation criteria as the norm.

Self-Improvement in Weight Space and Self-Play. A parallel line closes the loop through
parameter updates instead of code edits. Meta-learning optimizes the learning dynamics them-
selves [45, 46], while inference-time refinement improves single outputs through verbal self-critique
without keeping gains across tasks [47]. Rejection-sampling self-training [41, 48], optionally guided
by learned self-critique [49], and self-play fine-tuning [50] bootstrap a policy from its own fil-
tered generations. Self-rewarding models [18] also act as their own judge; SCoRe [51] trains self-
correction directly, related work rewards the reflection step [52], and SEAL [53] learns to write its
own fine-tuning data and update directives. Proposer–solver(–judge) frameworks generate their own
curricula: R-Zero [54], Absolute Zero [55], SPICE [56], and Language Self-Play [57] pose increas-
ingly hard challenges, Multi-Agent Evolve [58] trains proposer, solver, and judge from one base
model, and CURE [19] co-evolves a coder with its unit tester. Closest to our work, SCORE [20]
observes that static evaluators saturate and co-trains evaluator and solver with shared parameters,
and EvoRubrics [59] co-evolves a rubric generator adversarially with the policy. These methods
mostly co-adapt generator and reward inside gradient-based training. The RQGM instead searches
over agentic codebases and gates evaluator promotion on an external anchor, in line with evidence
that self-correction is unreliable without external feedback [60].

Learned Evaluation and Its Biases.  Our evaluators build on LLM- and agent-as-a-judge evalu-
ation [15, 61, 62], benchmarked for agreement with human preference [25]. Judges show position,
verbosity, and self-preference biases [15, 16, 63, 64]; self-preference tracks a model’s ability to
recognize its own text [22] and persists even when the judge’s own output is worse [65]. Peer re-
view, our paper domain, is especially exposed: LLM reviewers lean toward acceptance [66], favor
prestigious authors [67], and are fooled by laundered papers [68] and by agents optimized to write
convincing but unsound work [69]. Mitigations such as juries [70], adversarial hardening [71], and
evaluator lifecycle management [21] mostly keep the judge outside the system it scores. Zhang et al.
[21] come closest: they co-evolve metrics with agent skills under ground-truth guards and show the
anchor keeps the metric reliable. The RQGM shares this anchor discipline but places it inside recur-
sive self-improvement, and uses epoch boundaries to add adversarial objectives, such as replaying
papers a displaced reviewer accepted, that target generated artifacts absent from the anchor.

Reward Hacking and Non-Stationary Objectives.  Optimizing a fixed proxy invites exploita-
tion. Reward hacking has been formalized [17] and follows Goodhart-style overoptimization curves
against learned reward models [72]; a recent survey frames it as a consequence of compressing intent
into a scalar [73], and policies learn proxy gaps as a reusable skill that adapts when the evaluator
changes [74]. Contemporaneous theory argues that a static proxy has a receding “verification hori-
zon” [75]. Live benchmarks [76, 77] refresh test data against contamination and saturation [11, 12],
but benchmarks are costly to build, and changing one mid-run invalidates a search’s evidence. Con-
trolled utility evolution addresses this: the utility changes only at epoch boundaries, and selective
erasure keeps each epoch a fixed-criterion search.

Multi-Agent Co-Evolution and Open-Endedness.  Co-evolution against a moving target is old
in evolutionary computation: fitness sharing [78] and self-modifying policies [79] co-adapt popula-
tions, and self-play trains an agent against stronger versions of itself [80, 81]. LLM-agent versions
share experience across populations [82], play adversarial strategy–environment games [83], co-
evolve evaluators from opponent pools [84], or jointly optimize interacting components [85], and
human–AI co-improvement adapts the signal through human feedback [86]. Open-ended search
aims at endless novelty [87, 88], often through quality-diversity archives [89, 90] or growing skill
libraries [91], increasingly with foundation models [5, 92–94] and toward a closed self-referential
loop [95]. The RQGM instead changes the learned evaluation criterion itself at explicit epoch bound-
aries, with epoch-local validity.

Automated Scientific Discovery.  Our open-ended domains belong to the effort to automate re-
search end to end. The AI Scientist produced the first fully AI-generated paper to pass workshop peer
review [5, 6], and Co-Scientist [96], Robin [97], AlphaEvolve [92], and evolutionary multi-agent sci-
entists [98, 99] now cover hypothesis generation through experiments and write-up. These pipelines
typically fix their model judges per run, and critiques highlight automated evaluation as a key re-
liability risk [68, 100]. The RQGM lets the reviewer, grader, and code reviewer co-evolve with the
writers, provers, and coders they score, anchored to APReS decisions [25], IMO-GradingBench
grades [7], and accept/reject labels from CRAVE [27].
