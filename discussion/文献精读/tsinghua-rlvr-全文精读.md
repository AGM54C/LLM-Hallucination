## 1. 论文的实际问题与评价对象（pp.1–5）

作者区分平均输出表现与给定采样预算内可覆盖的问题集合，问当时的 RLVR 是否只是增加已有成功路径的采样概率，还是增加可以解决的问题范围。数学主要采用 base 直接 zero-RL，代码和视觉任务则往往从 instruction-tuned 模型出发；不能将所有 start model 都说成纯预训练模型。

§2.1 把 verifier 理想化为当且仅当最终答案正确时奖励为1。这是实验任务中的奖励设定，不是对任意科学验证器可实现性的证明。§2.2 明确 pass@k 是考察潜在能力覆盖，不是实际部署的选答效用：它在 k 个样本中有一个过检即算成功，却不解决部署者如何选出那一个。作者承认数学终局答案可能猜中，并用部分人工 CoT 检查缓解。

主评价温度 T=0.6、top-p=0.95、通常最大16,384 tokens；代码 DeepCoder 使用32k。base 与 RL 使用相同零样本提示，避免少样本示例带来的额外信息（pp.5–7、29–31）。同一采样次数并不意味着同一 token/时间成本；对能力和成本的论证需要分开。

## 2. 三类任务中的观察（pp.6–7）

数学覆盖 Qwen2.5 7B/14B/32B、LLaMA-3.1-8B、Qwen2.5-Math-7B，训练与评测包含 SimpleRLZoo、Oat-Zero、DAPO。主图表现为小 k 下 RL 占优、大 k 下 base 追上或反超。编码以 CodeR1、DeepCoder 与起点比较，视觉以 EasyR1 训练 Qwen2.5-VL-7B，对去除选择题的 MathVista/MathVision 测试。

作者人工检查低成功率样本：GSM8K 的25道困难可解题，base 有24道至少一条正确 CoT，RL 有23道；AIME24 的详细筛选与人工检查见 p.21。该检查支持“并非所有成功都是瞎猜”，但不等于证明全部轨迹逐步正确，也不是对所有基准进行完整过程标注。

图3在 DeepCoder/LiveCodeBench 上主要呈现高 k 差距缩小、末端接近；不宜用全称断言抹平图中差异。图9的 Magistral 也应按“差距缩小”解释。

## 3. 覆盖、困惑度与算法比较（pp.8–11）

Table 2 的 AIME24（k=1024）中 base-only 为13.3%，RL-only 为0%；MATH500（k=128）分别为3.6%与1.0%。附录 p.24 进一步报告把后者约5道题的 base 采样增至1024后均能解决。因此，正文的“近似子集”有经验支持，但有限采样结果与扩大预算后补充检查不可混为同一预算对照。

困惑度分析主图只随机取两道 AIME 题，每模型16条输出，o1为8条；附录补充前10题、每题32条的训练动态。较低 PPL 表示 base 对给定序列平均 token 预测较容易；它不能单独证明会在合理预算中采出整条长序列，更不能证明语义策略集合严格不变。论文没有给出“任何 RL 都无法超越 base”的数学不可能性定理。

算法比较为 PPO、GRPO、Reinforce++、RLOO、ReMax、DAPO；共同用 VeRL、Omni-MATH-Rule 2000训练/821域内测试、MATH500域外测试。通常去掉 KL。论文定义 ΔSE 为 base 的 pass@256 与 RL 的 pass@1 差；这是作者选择的参考指标，不是证明过的理论最优差距。DAPO 动态采样每批需额外约3–6倍样本（p.23），故算法曲线不能当作严格同总预算结论。

必须保留的表内例外：p.23 Table 3 的 MATH500，base pass@256=96.2，而 GRPO/PPO=97.2、RLOO=97.4、ReMax=96.6、Reinforce++=96.8、DAPO=96.4。Omni-MATH-Test 中部分算法也略高于 base。因此不可转述为“论文所有 RL 实验的高 k 都低于 base”。较稳妥结论是：所测设置常见平均成功率与覆盖面的分离，未形成一致、显著的大幅能力范围扩张。

Table 4（p.23）则清楚展示训练延长后的权衡：Omni-MATH-Train GRPO step150→450，pass@1从26.1到42.5，而 pass@256从66.3到64.3；域内测试 pass@256从68.3到63.9。MATH500 初期高 k 有轻微增益、后期回落。因此还须区分“早期提升”“后期丢失”和“从不可能提升”。

§4.4 将 rollout n从8提高到32，但附录说明 n=32只训220步、原设定450步且未收敛，不能当作完整排除充分扩展训练的实验。§4.5及 p.25 已有温度扫描与大致熵匹配；不能再批评最新版本完全未控制温度。该对照集中于 Qwen2.5-7B/SimpleRLZoo 的若干任务，并未覆盖所有训练策略。§4.6 讨论专有模型难以隔离纯 RL、R1-Zero的吞吐成本，Magistral 高 k 差距缩小；作者明确保留更大训练预算问题。

## 4. 机制解释、未来方向与局限（pp.11–13）

作者把巨大 token 动作空间、预训练先验和稀疏终局奖励视为候选原因。先验让可行采样成为可能，也可能限制探索；这段是机制解释，不是经过单一变量充分排除的因果定理。

作者自己提出四条出路（p.12）：程序等高层空间探索、循序渐进数据与子技能课程、中间过程奖励和细粒度归因、多轮 agent 与环境交互。最后一项明确包括搜索和实验获取新信息。§7 的范围限定是当前可得纯 RLVR 模型与训练方法，承认后续方法可能缓解。因此不能据本篇否定广义 RSI 或工具/代码层面的改进。

## 6. 全文阅读发现的一个过程检查例子（p.27，Figure 20）

公开 PDF 将该条轨迹标为 “Correct Response”。最终73是正确答案，但展示的最终推导含两处相抵的算术错误：`195+367+562+900=2024`，图中写成1924；`437+2×234=905`，最终又写成805。两项各少100，差仍为1119，于是最终得到73。已对照渲染图片，排除纯文本抽取造成的数字错读，并用直接整数计算复核。

正确的短计算是 `(2024-900-437-468)/3=73`。这个单例表明，最终答案对、出现“重新思考”的文字，都不能自动证明最终展示的推导链每一步有效。它与用户想做的过程验证器直接相关。

**解释边界：**这里检查的是论文公开展示的轨迹，不掌握原始生成日志，无法排除转录或排版造成错误；也不能据一个案例判定整篇论文的人工核验或核心现象失效。链中被明确撤回的探索性错误，与最终仍被采用的错误必须区分，本例关注后者。

## 7. 对当前科学验证器想法的启发

1. 生成成功率、推导有效性、给定预算下的能力覆盖，是三个不同的评价对象。训练只奖最终结论可能保留过程错误，科学工作流也可能“数值真但验证声明过强”。
2. 需要把验证器同样放在能力—覆盖—成本坐标下：误放减少是否来自全部拒绝，认可的正确主张范围是否缩小，增加预算是否只是多次挑选。
3. 禁止自行增加未证前提可以约束证明/认证权限，但不能创造实验信息。固定可靠规则仍可帮助发现新的推导，不能反过来推断所有进步都必须来自更强教师。
4. 主论文已明确提出细粒度奖励、课程与 agent 交互；这些不能当作本项目独有的新思想。真正的候选差异仍须落实到科学主张与证据资格在迭代中如何被改变，以及怎样以独立判据区分有效进步与验证标准变松。

本篇不证明 RSI 不可能，不证明受限验证器必然可靠，也不证明我们当前候选已经具有原创性。
