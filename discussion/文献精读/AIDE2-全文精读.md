## 1. 改进对象与两层结构（pp.1–5）

本文改写 agent 周围的代码，即控制搜索、上下文与验证的 harness，而不是训练基础模型权重。内层用固定预算优化具体任务代码，得到候选解，依据公开反馈 `r_pub` 选解；外层改写内层 agent，用其在任务私有数据上的聚合分数 `g(a)` 选择改写版本。被接受的版本成为下一轮要改写的代码。

关键权限区别：私有数据对内层不可见，但外层能读历次 `g(a)` 并据此优化。因此私有分数对外层来说是选择信号，不能当作从未参与任何优化的终审测试。作者 pp.6–7 另设四个不影响选择的外部基准，这是完整评价逻辑的一部分。

主运行的外层改进者是固定的人类开发系统 AIDEhuman，底层 claude opus 4.7；每个内层候选用 gemini 3 flash，模型在各循环内固定。主运行并非每次都自动把新内层 agent 提拔为更强的外层改进者；该问题由单独 ignition test 检验。因此本文把“持续编辑自身代码”称 RSI，与 Chen 综述对 open-ended RSI 的更强定义不同，报告中必须说明各自对象。

## 2. 连续改进与外部泛化（pp.5–7）

8天的主运行含初始节点及99次改写提案，接受7次，节点2、6、28、39、47、63、85；选拔分数从0.703到0.778。另两次完整运行接受2次、4次。选择曲线按历史最大分数本来就单调，不能独自证明真实能力单调；作者明确区分 selection 上的一阶泛化和新基准上的二阶泛化。

外部比较 AIDE0、AIDE47、AIDE85、AIDEhuman。ALE-Bench 为10题×10 seeds，MLE-Bench为22题×3，FML-Bench18题×3，WeatherBench 2衍生任务为1题×3。最后者是优化物理动力内核，对未修改内核计算 forecast-skill gain，不是 WeatherBench 2 官方排行榜上的绝对性能。

| 外部指标 | AIDE0 | AIDE47 | AIDE85 | AIDEhuman |
|---|---:|---:|---:|---:|
| ALE 私有 contest performance | 1536±33 | 1713±26 | 1790±9 | 1511±35 |
| MLE 私有 percentile | 0.678±0.006 | 0.730±0.005 | 0.722±0.011 | 0.708±0.007 |
| Weather 衍生任务 skill gain | 0.262±0.205 | 0.798±0.003 | 0.793±0.005 | 0.404±0.193 |
| FML normalized test improvement | 15.0±0.9% | 19.7±1.2% | 19.9±1.1% | 19.6±1.0% |

数值来自p.24 Table 1，±为一个标准误。AIDE85不在每项都优于AIDE47；FML与人类基线差值相对于误差很小，不应写成四项均显著超越。可以说进化版本在这些测试上改善AIDE0、与强基线相当或更好。Weather只有一个任务，不能据此声称广泛科学领域泛化。

## 3. 奖励投机、具体改写与无效机制（pp.8–10）

论文将38个未参与筛选的 kernel–training context 对用于评测：优化时看孤立 kernel speedup，再将其放入GPT-2/ViT/CNN训练循环。p.25给出的判据是孤立提速超过1.02倍且不到一半提速保留或在真实训练中崩溃。按该定义，reward hacking率为55%→39%→32%，人类基线39%。这不是任意欺骗率/幻觉率，也不能据轨迹相关变化将机制归因于某一修改。

agent代码中出现的改进包括：UCB1选择五种起草策略、部分softmax探索，每五步将最佳解转到另一策略分支；有界上下文摘要；当bug率≥15%时引入最多三种重复错误记忆；提醒私有测试、拦截极短空代码。

一个值得学习的负结果是“按距高分候选中位数远近作惩罚”的规则：作者回放发现该惩罚保持排序，所以从未改变选择。不能把存在一个模块当作它有因果贡献。

另一个修改修复了评测脚本的异常处理：原来单个测试失败会使全部测试崩溃，改成局部失败。这表明一概冻结所有评测实现也可能保留真实bug。需要区分修复执行与改变被检验的科学标准；本文未提供开放科学语义等价证明。论文把这个改写解释为修复而非钻空子，不应在没有原始代码审计时反向指控其属于作弊。

## 4. 改进者有没有变得更会改进（pp.10–11）

Ignition test 从相同AIDE47内层起点出发，只换外层为AIDE47或AIDEhuman，每组3 seeds、每次50步。终点均值分别0.780和0.782。AIDE47组看起来更早到达较高区域，但样本少、嵌套噪声大，作者明确判为 inconclusive，不声称更高采样效率或哪一方更强。

因此可以接受“代码层自改进带来可迁移的研究效率提升”的有限实证，不能据此宣称“已证明改进能力递归加速”“已点燃智能爆炸”，也不能把一次任务分数提高自动称为更强的改进算子。

## 5. 相关工作、机制局限与可复现细节（pp.11–14、24–28）

相关工作把程序搜索、自动研究、harness搜索、自指改进、元学习分开；已有统计接受门控 SGM、共同演化评价者 Red Queen 等入口。这里仅记录本文的引用关系，不把那些来源自动算成精读。

讨论指出内层搜索与评测双重噪声可导致外层错误接受，一次错误版本成为incumbent会影响后续路径；复杂改写代码难以归因、可能含闲置逻辑。这是作者明确承认的边界。

附录A的约束并非全部都是同美元预算：ALE/MLE每run $5，Weather $15；FML主要限制100步，kernel20步。不同基准底层模型也不同，各基准内部则统一；所谓“全部严格同总计算量”是不准确的。基线出现context超限时以终止时的最佳候选计分，FML有5次、较大预算ALE有48次。选择基准的完整逐任务实现、全部选拔开销在该PDF中未列全，不能认为仅凭本文文字即可完整复现。

附录B说明人类基线与其他已发表代码优化agent比较，领先者间差相对误差很小。附录C把ALE/MLE预算改为$20，对不同基础模型检查harness迁移；最强模型在MLE上的收益位于一个标准误内，不能写成所有模型显著受益。附录D记录被拒绝提案，约四分之一被拒绝的已评分版本在公开指标上更高、却在私有指标上更差；“加个LLM裁判”“多数投票”均不能由直觉假设有效。附录E检查全部历史上下文与有界摘要的字符长度，末端压缩约7–50倍，但没有用单一消融充分分离所有代码改写的贡献。

## 6. 对科学验证器的直接启发

1. 将调试信号、迭代选择信号和最终外部评价分开；一个数据集对内层隐藏，并不等于它对整个研究过程仍然独立。
2. 验证器本身也可优化查证顺序、程序、记忆和检验实现，基础模型权重不变仍可获得系统收益；这与清华RLVR的权重训练边界属于不同对象。
3. 若改进的验证器要替换旧验证器，必须重新确认它检验的是同一主张、相同适用条件。评测实现修bug与放松证据要求必须分开核验。
4. 对“验证器能促进持续科学发现”的强论断，除了当前错误识别率，还应评估后续改进能力以及错误认证的累积。AIDE²本身已显示这一更强检验可能无法得出结论。

这篇没有解决科学假设真值判定，也没有证明自我改进不需要外部信息。它提示一个可借鉴的评价设计，而非直接证明新研究想法有效。
